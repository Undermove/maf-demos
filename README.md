# Демо к докладу про Microsoft Agent Framework (MAF)

Пять маленьких самодостаточных проектов в одном солюшене `MafDemos.sln`, которые
показываются вживую во время доклада. Идея каждой демки: сначала схема на слайде → потом запуск.

## Настройка ключей (один раз)

Ключи кладутся в **`appsettings.local.json`** — он в `.gitignore` и **не попадает в git**.
В каждом проекте:

```bash
cp appsettings.local.json.example appsettings.local.json
# открой appsettings.local.json и впиши ключи
```

Для своего OpenAI-совместимого шлюза задай `OpenAI:BaseUrl` (с `/v1` на конце) и при желании
`MiniModel` / `StrongModel`. Ключи можно передать и через переменные окружения
(`OpenAI__ApiKey`, `GitHub__Token`).

## Demo A — агент + один read-only тул (после слайда про базовые абстракции)

`A_CountryOpeningDemo/` — самый простой живой агент: модель + инструкции + **один тул** `ReadFile`,
который ходит в **настоящий GitHub** (демо-репозиторий
**[Undermove/maf-country-opening-demo](https://github.com/Undermove/maf-country-opening-demo)**).
Вся конфигурация спрятана в `#region config` — на экране остаётся суть: создали агента,
дали тул, запустили.

> Прочитай countries/germany.json и расскажи, о чём этот файл.

В консоли виден вызов тула (`🔧 ReadFile(...)`, серым) и человеческий пересказ содержимого.
Тул read-only — идеальный первый шаг: агент уже взаимодействует с внешней системой,
но сломать ничего не может.

В `GitHubTools.cs` рядом лежат и «взрослые» тулы (`CreateBranch`, `CommitFile`,
`CreatePullRequest` с `ApprovalRequiredAIFunction`) — они не зарегистрированы у агента,
но подключаются одной строчкой, когда доклад дойдёт до кейса открытия стран и human-in-the-loop.

Нужен **GitHub PAT** со scope `repo` (в `GitHub:Token`).

```bash
cd A_CountryOpeningDemo
dotnet run
```

## Demo B — «проблема»: mini наглядно ломается на грузинском

`B_BadTranslationDemo/` — мотивация для роутинга моделей. **Никакого MAF** — голый `IChatClient`
и два прямых вызова, весь код — один экран. Маркетинговый **текст-ловушка** (бренд + англицизмы +
идиома, подобран экспериментально — mini ломается на нём стабильно):

> Встречайте Додстер-комбо: кешбэк звёздами, лимитированный мерч и пицца,
> которая разлетается как горячие пирожки.

переводится на грузинский сначала mini-моделью, потом старшей. Зал грузинский не читает,
поэтому фишка демо — **обратный перевод**: старшая модель дословно возвращает результат
на русский, сохраняя все ошибки. Контраст виден сразу:

- **mini** (красным): «Интерактивируйте донстер-комбо… лимитированный мерси» — каждый прогон
  ломается по-новому (то «комбо мотиваторов», то «горячие чаты», то корейский слог в грузинском слове);
- **strong** (зелёным, `Temperature = 0`): чистый корректный перевод — детерминированно,
  каждый прогон одинаковый.

```bash
cd B_BadTranslationDemo
dotnet run
```

## Demo C — «решение»: хендофф на старшую модель (воркфлоу в 3 строчки)

`C_TranslationHandoffDemo/` — тезис «роутимся между моделями ради точности перевода»
через **готовую оркестрацию** `AgentWorkflowBuilder` — весь воркфлоу:

```csharp
var workflow = AgentWorkflowBuilder
    .CreateHandoffBuilderWith(dispatcher)                       // диспетчер на mini
    .WithHandoff(dispatcher, expert, "Target language is low-resource (ka, hy, ...)")
    .Build();                                                   // эксперт на strong
```

Никаких executor'ов, рёбер и агрегаторов: MAF сам даёт диспетчеру tool для хендоффа и
переключает разговор на эксперта. В консоль стримится **вся цепочка решений**: из
`update.Contents` печатаются не только реплики, но и `FunctionCallContent` — виден сам
вызов хендоффа с причиной (`🔀 dispatcher вызвал handoff_to_1 → expert_translator
({"reasonForHandoff": "..."})`) и ответ тула (`↩ Transferred.`). Нюанс MAF 1.13: имя
handoff-тула генерится как `handoff_to_<порядковый номер>`, поэтому демо подписывает цель стрелкой.

Тот же текст-ловушка из Demo B, два перевода подряд:

- **Spanish (es)** → `dispatcher` (mini) переводит сам — большой язык ему по зубам;
- **Georgian (ka)** → `dispatcher` молчит и передаёт управление → отвечает `expert_translator`
  (strong, `Temperature = 0`, экспертный промпт) — и тут бонус: эксперт ещё и **локализует идиому**
  под Грузию — «пицца, которая продаётся так быстро, как горячий хачапури».

Решение о хендоффе принимает **LLM** (как в бонусной демке с agent-as-tool, но оркестрацию делает MAF).
Рядом в MAF есть и другие готовые паттерны: `BuildSequential`, `BuildConcurrent`, GroupChat,
Magentic, а для полного контроля — низкоуровневый `WorkflowBuilder` с условными рёбрами графа.

```bash
cd C_TranslationHandoffDemo
dotnet run
```

## Demo D — пайплайн открытия страны: БД + доска + человек в цикле (прод в миниатюре)

`D_CountryPipelineDemo/` — финальная демка, повторяющая боевую схему support-bot:

```
while (в БД есть шаги)            ← детерминированный каркас: цикл и порядок — КОД
    шаг (YAML) из SQLite  →  агент выполняет шаг тулами  →  шаг помечается done
```

- **Ямлики шагов — один в один как в проде** (support-bot / country-opening-template):
  `card` с `id/name/lane/depends_on/required_data` и `checklists` с items
  `{id, depends_on, type, instruction}`. `type: ai` — агент делает сам,
  `type: manual` — агент спрашивает человека (`AskManager`).
- **«БД»** — SQLite-файл `pipeline.db`, сидируется тремя шагами; когда все выполнены —
  сбрасывается для нового прогона. При изменении сидов — удалить файл из bin.
- **Доска** — настоящий GitHub Projects v2: [«Открытие стран (MAF demo)»](https://github.com/users/Undermove/projects/6),
  привязан к репозиторию, карточка — [issue #4](https://github.com/Undermove/maf-country-opening-demo/issues/4).
  `MoveCard` двигает карточку по колонкам (Status-филд через GraphQL, id резолвятся динамически)
  и дублирует статус лейблом `status:*` на issue. Токену нужен scope `project` (+`repo`).
- **Тулы разнесены по классам**: `BoardTools` (доска), `GitHubTools` (git), `TelegramTools`
  (человек) — у каждой внешней системы своя дверь.
- **Человек в цикле, два вида**: свободный вопрос (`AskManager` — агент реально блокируется
  и ждёт ответа) и подтверждение действия (`ApprovalRequiredAIFunction` на открытии PR).
  Если задан `Telegram:BotToken` — оба уходят в Telegram (вопрос — сообщением,
  подтверждение — инлайн-кнопками ✅/❌); без токена — fallback в консоль.
- **Одна сессия на весь пайплайн** — языки, выясненные на шаге 1, агент сам использует
  в конфиге на шаге 2.

Сценарий: шаг 1 — читает карточку, спрашивает языки у менеджера, комментит и двигает
карточку; шаг 2 — конфиг по образцу germany.json в новой ветке; шаг 3 — PR
(с подтверждением) + ссылка в карточку + карточка в done.

```bash
cd D_CountryPipelineDemo
dotnet run
```

> Сброс демо (перед показом и после): `dotnet run -- reset` — закрывает PR и ветки,
> переоткрывает и чистит карточку (доска сама закрывает issue при Done), возвращает её
> в backlog/Todo (в т.ч. из архива) и сносит локальную БД шагов.

## Бонус — роутинг через agent-as-tool (без Workflow)

`TranslationRoutingDemo/` — тот же кейс роутинга, что и Demo C, но руками через
**MAF-суб-агентов** (`AsAIAgent` + `agent.AsAIFunction()`): малая модель-**диспетчер** сама
решает — если целевой язык «малый» (ka, hy, az, …), она НЕ переводит сама, а зовёт
**суб-агента-эксперта на старшей модели как инструмент** (agent-as-tool). Это ровно
«модель увидела, что нужна другая модель, и отдала часть задачи».

**Сценарий «было → стало»:**
1. Запускаем как есть — агент на **малой модели**, переводит грузинский сам. В консоли:
   `✔ реально ответила модель: gpt-4o-mini` (из `ChatResponse.ModelId`).
2. В `Program.cs` **раскомментируем блок «ВАРИАНТ 2»** (и закомментируем «ВАРИАНТ 1»):
   диспетчер получает `expert_translator` как тул. Запускаем — видно **хендофф**:
   `✔ ... gpt-4o-mini` (диспетчер подумал и вызвал тул) → `✔ ... gpt-4o` (эксперт перевёл).

У каждого суб-агента может быть **свой набор тулов** — это и есть «ИИ работает ровно там, где надо».

```bash
cd TranslationRoutingDemo
dotnet run
```
